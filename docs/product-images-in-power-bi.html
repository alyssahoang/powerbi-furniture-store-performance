Product Images in Power BI

Four patterns that work, one that doesn't, and the three constraints that break every attempt — demonstrated on the 80-SKU furniture catalogue.

Start here

Three constraints decide everything

Nearly every broken product image in Power BI traces to one of these. They are worth checking before you build the visual, because each one fails silently — a blank cell, never an error message.

ConstraintThe ruleHow it fails
Anonymous access The URL must load with no sign-in. SharePoint and OneDrive for work/school are not supported. OneDrive for home embed codes and OneLake file links are the only exceptions. Blank cells for everyone but you — it renders on your machine because your browser session is authenticated.
File format BMP, JPG, JPEG, GIF, PNG, SVG only. A URL that returns an HTML page instead of image bytes shows nothing. This is the usual Google Drive and SharePoint failure.
Text cell length Power Query truncates any cell over 32,766 characters. Only relevant for base64. The string is cut mid-stream and the image half-renders or fails outright.

The 20-second test. Copy one URL from your data and paste it into an incognito window. If a raw image doesn't fill the tab, Power BI cannot render it either. No amount of Data category fiddling will change that.

Hosting

Your Google Drive links are already correct

Worth stating plainly, because it's the step most people get wrong: the DIM_img query builds final_url as

https://drive.google.com/thumbnail?id=<FILE_ID>&sz=w1000

That is the format that returns image bytes. The uc?export=view&id= form in the original image_url column returns an HTML viewer page, so it renders nothing — and that column is also flagged Data category = Image URL in the model. Hide it, or someone will drag it in and spend an afternoon on blank tiles.

Set sz=w1000 no larger than you need. Drive serves the full resolution you ask for, and an 80-row table pulling 1000 px JPEGs is 80 network round-trips before the visual paints.

Three tiles from one measure, driven by 'Hero Rank'[Value] on the visual.

-- Modeling → New table
Hero Rank = GENERATESERIES ( 1, 3 )   -- leave it unrelated

Hero Image =
VAR R = SELECTEDVALUE ( 'Hero Rank'[Value] )
VAR Ranked =
    ADDCOLUMNS ( ALLSELECTED ( DIM_product[product_id] ), "@Sales", [Sales] )
VAR Pick = TOPN ( 1, TOPN ( R, Ranked, [@Sales], DESC ), [@Sales], ASC )
VAR Pid = MAXX ( Pick, DIM_product[product_id] )
RETURN
    LOOKUPVALUE ( DIM_img[final_url], DIM_img[product_id], Pid )

The step everyone misses. Select Hero Image in the Fields pane, then Measure tools → Data category → Image URL. Measures carry the category just like columns, and without it the card renders the raw URL as text.

The nested TOPN is how you reach the Nth item: take the top R, then take the smallest of those.

Avoid · the whole catalogue

Every SKU, image column, no Top N

The failure mode. All 80 products in one scrolling table with a picture on each row: 80 HTTP requests before the visual paints, thumbnails too small to identify anything, and a reader who scrolls instead of comparing.

Sizing

If you embed images in the model

Hosting is simpler, but base64 in the model makes the file self-contained — no network, no broken links, works offline. The 32,766-character cell limit decides whether it's viable, so here is where that limit actually lands, measured on 20 of your own product PNGs:

ThumbnailJPEG qualityLargest base64 stringVerdict
150 px755,444Safe
220 px759,568Safe
300 px8520,592Safe
400 px7523,220Safe — best quality-per-byte
400 px8531,840Safe, but only 926 characters of headroom
512 px7534,108Truncated
512 px8547,648Truncated

400 px at quality 75 is the sweet spot — sharp at every size in this guide, and roughly 9,500 characters clear of the ceiling. Above 512 px you need the split-across-rows-and-reassemble-with CONCATENATEX workaround, which is real but rarely worth it for a product catalogue.

The string must carry its data URI prefix, or Power BI treats it as a filename:

data:image/jpeg;base64,/9j/4AAQSkZJRgABAQ…

Before you ship

Seven checks

  • Every image URL opens as a raw image in an incognito window.
  • The URL column — or measure — is set to Data category = Image URL.
  • The broken image_url column is hidden so nobody uses it by mistake.
  • Image size is set explicitly under Format → Visual → Image size, not left at the default.
  • Any table with images has a Top N filter capping the row count.
  • Images are served at display resolution, not 1000 px scaled down in the browser.
  • It has been checked in the Power BI service, not just Desktop — Desktop borrows your browser session and will render links the service cannot.
